# Local native validation checkpoints

Muse binding v2 stores a content-free successful raw boundary inside the existing
protected registration. This foundation leaves real Muse capture fenced. Empty
locator resolution, inventory/cursors, hooks, setup, children and capture
activation belong to later work. Local explicit-file handoff stays independent
of capture authority.

The checkpoint means **last durably accepted complete local native validation**,
not remote acknowledgement. It records proof version 1, domain `muse-ordinary`,
algorithm `sha256`, positive raw byte boundary and lowercase SHA-256. It is bound
to the enclosing original agent/native ID, creation time, workspace, stream,
immutable path and root revision. The fingerprint stays local and is never copied
into source bundles, metadata or handoff artifacts. Retained-source hashes and
retained record counts cannot replace it.

A collector-private prepared lease keeps the exact snapshot and input alive
through complete concrete Filter success, output-size checks, proof verification
and atomic local commit. Provisional startup facts read bounded raw physical
lines with the existing strict decoder and root predicates, including exec,
MSP and the exact two-metadata lane. They grant neither consent nor uniqueness.
Binding facts require independently supplied binding context; arbitrary explicit
files can supply content equality without inventing a root revision. Selected
local handoff reuses an attested live snapshot for its final named-path/content
verification and refuses changed size or modification time, replacement and
same-stamp rewrites after filtering. Its baseline and final content hashes each
stream the raw boundary; this does not grant native capture authority. Ordinary
providers retain their independent second-handle local recheck. Native
binding facts require the ordinary dated UUID/session.jsonl layout and matching
body owner. Production native-root/capture contexts still refuse before reads.

The dedicated state commit stages and fsyncs outside hooks.lock, independently
verifies the live source after staging on every bounded retry, then takes
hooks.lock followed by the request lock. Current policy, setup, removal,
destination, exact root, immutable owner and exact expected previous checkpoint
are checked before rename. Later hook/HEAD observations survive an overtaking
retry. Directory sync occurs after lock release. Native reads, hashes, physical
project checks and staging never run under hooks.lock. External filesystem
writers are not serialized by these local state locks.

Only that prepared path may create or advance a checkpoint. Advancement requires
an independently matching previous raw prefix, nondecreasing boundary and the
same digest at an equal boundary. Generic saves, hooks, import and generation
copies may preserve the exact proof but cannot mint, drop or change it. Unknown,
dropped, malformed or downgraded proofs refuse. Historical Muse v1 lacks raw
continuity and cannot be silently reconstructed from today's source.

A failed Filter, limit, partial frame, cancellation or policy change leaves the
checkpoint unchanged, even if disposable scan state changes. Failed scan tokens
are negative equality results. Frozen publication retries retain their exact
bytes and never read newer native content or advance this proof. A crash after
checkpoint commit but before candidate staging can conservatively refuse future
continuation if the validated native bytes are then lost or rewritten. It cannot
fabricate publication or acknowledgement; retained publications remain readable.

Warm observations hash raw bytes in bounded scratch and compare strong signatures
in the existing scan cache. They do no full Filter, PUT or global inventory walk
when the ordinary collector equality gate succeeds. Warm disk work is linear:
current implementation performs two full raw hash passes plus bounded startup
prefetch. NativeReadBudget bounds live charged memory, not file length, cumulative
I/O or process RSS. Raw-input limits and caller cancellation remain separate.
The conservative first/changed paths also perform independent proof and previous
prefix passes; component measurements report actual descriptor bytes and calls.
No raw cache, second decoder or filesystem-atomic snapshot is claimed.

The native-only commit fence requires Muse explicitly selected in `Harnesses`,
archiving enabled, an explicit included project with a nonzero activation and
matching project ID/root, and both actual original native creation and owner
admission inside that current project window. The nearest configured cwd rule
must still select that owner; nested exclusions win. Physical worktree/alias
mapping is checked outside locks and cannot be inferred from a prefix. Imports,
children, frozen owners and recovery without a dedicated commit owner are refused.
The owner must carry a nonempty destination ID exactly matching a configured
current provider/bucket identity. A zero legacy DestinationSince is compatible
only under that exact explicit identity; a nonzero boundary also fences actual
native birth. Hook time cannot manufacture a later native creation or consent.

Native validation's destination window is a separate pure configuration predicate.
The general destination ownership check keeps its ID-first switch-away/back
semantics for existing sessions, frozen publication, imports and retention.
