PR 7 investigation
------------------
The complete-query >100 ms trigger is observed. This API intentionally returns
all N rows; it cannot acquire a page-sized decoding bound without changing its
contract. Profile representative bounded scope/prefix/text consumers before
choosing typed columns, indexes or an unused-count API change. Preserve complete
ambiguity and query-time label semantics. An index requires useful EXPLAIN QUERY
PLAN evidence and matched command-level improvement.

Refresh alone approaches 500 ms at 50k before real-provider latency or populated
body-cache inventory. Any unchanged-root or incremental refresh optimization
needs explicit corruption detection, completeness and repair semantics, while
retaining selected-row checksums and authoritative body validation. Matching a
root alone does not justify skipping validation. This evidence does not enable
catalog-v4 or claim its flat command target.
