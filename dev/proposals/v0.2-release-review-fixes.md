## A Correct handoff resolution and worktree paths

Owning code: `internal/cli/handoff_title.go`, `handoff_select.go`,
`list_browse.go`, `read_context.go` and `handoff_worktree.go`.

### Exact identity lookup

At the original review baseline, the `(harness, ok)` result collapsed missing
keys, read failures,
cancellation and several matching harnesses. A failed exact lookup then started
title search with a fresh read context. The title eligibility filter can hide
one matching physical session and make an ambiguous full ID appear unique.

- Return explicit outcomes for not found, unique and ambiguous, plus an error.
  Only a genuine not-found result may continue into the existing title search.
  Cancellation and an unreadable exact lookup must terminate resolution.
- Establish one cancellation owner for query resolution. Pass its context into
  exact probes, local discovery and `loadSessionsForBrowseContext`; use the
  existing read-phase ownership helpers when entering interactive phases.
  Check cancellation before accepting a result or initiating a launch.
- Preserve ambiguity across physical harness/session identities before applying
  prompt, replay, scope or current-agent eligibility filters within supported
  registered-harness probes. Return an actionable
  ambiguity diagnostic requiring `--harness`; never infer the harness from which
  session remains eligible for title search.
- Reuse existing exact metadata probes where their bounded lookup contract fits. Preserve explicit
  harness filtering, catalog authority and selected metadata/source verification.
  Do not replace an exact lookup with exhaustive archive enumeration.
- Preserve local-first behavior and offline local selection where already
  supported. Audit direct local-ID resolution for the same ambiguity contract.
  A remote cancellation must not become permission to continue locally.

Regression coverage must use valid metadata and checksum-verified sources, rather
than malformed sidecars. Cover cancellation during a blocked exact read; a real
miss followed by title search; an operational read error; two harnesses sharing a
full ID with one known-zero-prompt session; and explicit `--harness` selection.
Exercise `--to` and `--worktree` with a launch recorder: cancellation or unresolved
ambiguity must produce no launch, handoff file or worktree. Verify that cancelled
resolution does not start the fallback listing or another read phase. Existing
title, short-ID, replay, child, source-policy and offline tests must retain their
behavior.

### Git path output

Introduce a path-output helper for `rev-parse --show-toplevel` and `--show-prefix`
that removes only Git's terminating newline. Preserve meaningful path whitespace.
Keep normalization for branch names and commit hashes separate from path parsing.

Use a temporary real Git repository whose root ends in a space, with a nested
working directory. Assert that worktree creation succeeds, the launch directory
is correct and carried changes survive. Retain the existing dirty-tree, branch,
submodule and cancellation checks.

## B Bound active-source reads before allocation

Owning code: `internal/reader/reader.go`; capability contract:
`internal/storage/storage.go`. Follow the already stricter `LoadRevision` path.

- Validate the source reference and reject a declared compressed size outside
  the caller's limit before any object GET.
- Require `storage.LimitedGetter` for active-source downloads and call
  `GetLimited` with the validated declared size. Do not fall back to unbounded
  `Get` when the capability is absent. Production S3 and catalog stores already
  provide this capability; audit caller wrappers and test stores for forwarding.
- Preserve the 32 MiB compressed and 128 MiB uncompressed defaults, caller limits,
  checksum and identity verification, streaming decompression, schema refusals,
  cancellation and missing-object refresh behavior.
- Return a clear oversized-object or unsupported-store error using existing
  error conventions. Keep default limits unchanged unless a separate measured
  workload justifies changing them.

Use small fixtures to prove zero GETs for a known oversized reference; bounded
GET selection and its exact ceiling for a valid reference; refusal of a body
larger than its declared size; refusal of a store without bounded reads; and
successful reads at the limit. Retain corruption, missing source, identity,
compressed/uncompressed size and cancellation checks. Exercise active-source
consumers such as show, handoff and export with a real bounded store adapter.

## C Make validation reliable across supported environments

### Portable Python fixtures

Update `scripts/test_ci_tiers.py` to use a nonreserved branch name such as
`fixture-pr-head`, and fully qualified refs or recorded commit SHAs for fixture
merges. Verify the resulting merge has the expected base and head parents.

Canonicalize legitimate fixture roots with `Path(...).resolve()` in
`scripts/test_go_cache_context.py` and `scripts/test_go_cache_steps.py`; construct
their environment and expected cache paths from those roots. Keep deliberately
aliased, symlinked or unsafe paths unresolved in negative tests. Preserve the
production cache admission checks that reject unsafe ownership and aliases.

Run these modules on macOS with its ordinary temporary directory and on Linux.
Using `TMPDIR=/private/tmp` alone is a diagnostic workaround, not the fixture fix.

### Discovery compatibility and runtime investigation

`TestCompatibleFormatsPublishAndReadBackAmongRejectedRecords` failed during the
parallel scan budget and passed in isolation. Make compatibility coverage finish
through a bounded number of resumable passes, asserting the complete qualified
identity set, rejection classifications, verified publications and no duplicate
admissions. Do not assume every fixture fits within one real five-second pass.
Retain separate tests of the production deadline, checkpointing and cancellation;
do not increase the production discovery budget to make this test pass.

The review's full race run reached the 20-minute package timeout in CLI,
collector, discovery and state. Capture test JSON and durations for the affected
packages using the repository's supported CI runners. Distinguish fixture cost,
host contention and genuine hangs before changing code. If required CI also
times out, reduce repeated fixture setup or split full test bodies using the
existing discovery and evidence contracts. Preserve full coverage and durable
production barriers. Do not remove assertions or simply raise timeouts without
measured justification.

Use normal local permissions for localhost-server and process-group tests.
Run the repository-pinned linter version from `.github/workflows/test.yml` in an
isolated tool directory or CI; do not overwrite the user's installed linter.
Run script modules separately so an expensive purge matrix cannot hide failures
in the remaining installer and release tests. Execute the complete purge matrix
on the prescribed full-tier runner and retain its evidence.

Follow [the release runbook](../maintainers/releasing.md),

2. Stage the prerelease candidate from that same SHA using the existing release

3. Exercise the pinned candidate installer in disposable environments on each

4. Run independent disposable S3 and R2 records. Verify actual-app capture for
   Claude Code, Codex and Cursor where advertised; list/show/handoff; pause/resume;
   finite and forever retention; pairing; backfill/undo; native-loss durability;
   selectable history; uninstall/reinstall; and final safe cleanup. Follow the

   corresponding advertised support.
5. Record the completed evidence and use the existing promotion gate for the same
